# 4.11 No puedo cerrar caja: resolver mesas, pedidos y sesiones pendientes

Si YURES no permite cerrar caja, lea el mensaje y resuelva la operación real que sigue abierta. Esta ficha diagnostica bloqueos; el procedimiento completo de cierre está en [2.9 Cerrar caja al finalizar el turno](../paquete-2/2.9-cerrar-caja-al-finalizar-turno-conteo-reporte-confirmacion.md).

## 1. Hay mesas ocupadas

1. Vuelva al croquis y ubique las mesas indicadas como ocupadas.
2. Si el consumo fue cobrado, complete la liquidación para que la mesa quede disponible.
3. Si la mesa fue abierta por error o el cliente se retiró sin continuar, use **Liberar** sólo con la razón y el control descritos en [1.12 Cerrar vs Liberar mesa](../paquete-1/1.12-cerrar-vs-liberar-mesa-diferencias-y-errores-tipicos.md).

No libere una mesa con consumo real sólo para permitir el cierre.

## 2. Hay pedidos Delivery o Calle sin completar

1. Abra **ESTADO** y revise las pestañas **Delivery** y **Calle** que estén disponibles para la terminal y los módulos contratados.
2. Identifique qué pedido sigue en proceso y confirme su situación con cocina, mostrador o repartidor.
3. Para un pedido preparado, selecciónelo y use **Preparado**. Para un pedido que realmente salió a entrega o despacho, use **Despachado**; YURES no permite despachar un pedido todavía pendiente.
4. En **Calle**, **Despachado** completa automáticamente el registro de entrega; actualice **ESTADO** antes de reintentar el cierre.
5. En **Delivery**, **Despachado** puede seguir bloqueando: salvo que el negocio tenga configurado un flujo de dos pasos, el pedido permanece asignado al repartidor hasta que se complete la entrega real en **ENTREGAS**. Seleccione al repartidor, revise los pedidos asignados, marque el resultado real de cada uno y use **Finalizar**. No finalice una entrega que aún no ocurrió.
6. Si el pedido aún se muestra como **pedido**, use **Completar** para continuar su flujo de venta y liquidación; confirme el cobro antes de darlo por terminado. Una venta **Pagado** ya ingresó a caja y no debe modificarse por este motivo.
7. Actualice **ESTADO** y vuelva a intentar el cierre sólo cuando no queden pedidos activos.

Consulte [6.5 ESTADO y ENTREGAS](../paquete-6/6.5-botones-laterales-estado-y-entregas-que-resuelven-en-la-operacion.md) para el uso normal de esos controles. No anule, elimine ni marque un pedido como completado sólo para eliminar el bloqueo.

## 3. Hay sesiones de mesero o asistente abiertas

Pida a cada responsable que cierre su sesión operativa y que confirme que no deja pedidos pendientes. Este bloqueo se revisa cuando queda una sola caja abierta y el negocio tiene activado el modo manual de sesiones; por ello puede no aparecer en todas las instalaciones.

## Límites que pueden cambiar el resultado

La revisión de mesas sólo aplica a una terminal de tipo caja. Los pedidos Delivery y Calle pueden limitarse a la terminal actual o considerar todas las terminales según la configuración de ventas privadas; además, con cajas paralelas el resultado puede variar. No suponga que otro terminal resolvió el bloqueo: vuelva a ejecutar el intento de cierre y verifique el mensaje actual.

## Escalar

Si el pedido, la mesa o la sesión no corresponde a la operación real, deténgase y solicite revisión al responsable autorizado. Registre el caso; no fuerce el cierre ni use acciones de anulación como sustituto de la corrección.
